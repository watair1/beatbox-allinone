# 비트박스 올인원

**입으로 내는 소리를 연습하는 도구.** 패드는 악기가 아니라 귀로 듣는 기준점이고,
진짜 악기는 쓰는 사람의 입이다.

목표는 "잘하게 만들기"가 아니라 **증강**이다. 가장 잘하는 사람이 써도 늘어나야 한다.
그러려면 아직 아무도 안 낸 소리를 줄 수 있어야 하고, 그게 이 앱이 소리를 녹음이 아니라
**파라미터로** 만드는 이유다.

`index.html` 하나가 전부다. 빌드 도구도, 의존성도, 서버도, 음원 파일도 없다.
(`sw.js`는 오프라인 캐시 전용이고 없어도 앱은 그대로 동작한다.)

## 소리를 어떻게 만드나

녹음된 음원이 하나도 없다. 전부 Web Audio로 합성한다.

```
톤층 (파형 + 피치 스윕)  ┐
노이즈층 (하이/로우패스)  ├→  성도 색 (포먼트)  →  엔벨로프  →  소프트 클리퍼
파열 (어택의 터짐)        ┘
```

- **톤층** — 음정이 있는 부분. 킥을 킥으로 만드는 건 150Hz→50Hz로 떨어지는 피치 스윕이다
- **노이즈층** — 숨·마찰. 하이패스 주파수가 밝기를 정한다 (하이햇 7kHz)
- **파열** — 타격음의 정체는 처음 20~50ms의 터짐이다
- **성도 색** — 입·혀·비강의 구조. 필요한 소리에만 얹고 안 쓸 수도 있다

### 성도 색이 하는 일

| 파라미터 | 해부학 | 음향 |
| --- | --- | --- |
| `place` | 혀 앞뒤 | F2 (2400↔800Hz) |
| `open` | 입 벌림 | F1 (250↔950Hz) |
| `nasal` | 비강 결합 | 270Hz 공명 + 1.1kHz 안티포먼트 |
| `tense` | 긴장도 | 포먼트 Q |

**peaking 필터**를 쓴다. 밴드패스로 만들면 포먼트 사이 주파수를 전부 버려서
뭘 만들어도 관 속 웅웅거림이 된다 — 실제 성도는 강조만 하고 나머지를 통과시킨다.

### 그래서 새 소리가 나온다

소리가 이름이 아니라 **좌표**라서, 알려진 소리도 아직 없는 소리도 같은 공간 위의 점이다.
「탐색」에서 두 소리 사이를 밀거나 무작위로 뽑으면 그 사이의 빈 자리로 갈 수 있다.
마음에 들면 저장해서 패드에 올린다.

## 루프 길이는 뭐가 정하나

**첫 녹음 길이 + 자동 마디 스냅**으로 정했다.

| 방식 | 좋은 점 | 나쁜 점 |
| --- | --- | --- |
| 첫 녹음 길이 | BPM을 안 물어봐도 됨 | 끝을 어설프게 끊으면 절뚝거림 |
| 고정 마디 | 레이어가 항상 딱 맞음 | 시작 전 BPM 입력 = 진입 장벽 |
| **첫 녹음 + 스냅** | 자유롭고 안 절뚝거림 | 구현이 제일 어려움 |

BPM을 먼저 묻는 순간 "REC 누르고 그냥 치면 된다"가 깨진다. 그래서 그냥 치게 두고,
끝나면 길이를 재서 가장 가까운 마디로 반올림한다. 스냅은 끌 수 있다.

재생은 `setTimeout`이 아니라 `ctx.currentTime` 기준 미리보기 스케줄러다.
탭이 백그라운드로 가면 타이머는 throttle 되지만 오디오 시계는 계속 가므로 루프가 안 흔들린다.

## 밟은 함정들

앱 동작에 직접 영향을 준 것만.

- **게이트가 닫혀도 입력을 먹었다** — `#gate{display:flex}`가 id 선택자라 `[hidden]` 기본 규칙을 이겼다
- **지속음이 누르자마자 사그라들었다** — `exponentialRampToValueAtTime`은 *직전에 예약된 이벤트 시점*부터 램프한다. release 시점에 값을 못 박지 않으면 램프가 어택까지 거슬러 올라간다. `cancelAndHoldAtTime`은 취소할 미래 이벤트가 없어 무력했다
- **리미터가 소리 균형을 뒤집었다** — `DynamicsCompressor`는 내부 메이크업 게인 때문에 지속음은 0.45→0.575로 키우고 짧은 타격음은 0.45→0.09로 눌렀다. tanh 소프트 클리퍼로 교체
- **빠른 롤이 동시 타격으로 오인됐다** — 시간이 아니라 입력원(`pointerId`)이 다른지로 판정
- **공유 링크가 깨졌다** — `file://`에서 `location.origin`은 문자열 `"null"`이다. `location.href`에서 해시만 떼어 쓴다
- **WAV 내보내기가 앱을 날렸다** — 렌더링을 `await`한 뒤엔 사용자 제스처 컨텍스트가 끊겨 있어서, 그때 다운로드를 프로그램으로 클릭하면 새 탭이 차단되고 현재 탭이 blob으로 이동한다. 링크만 띄우고 누르는 건 사용자에게 맡긴다

## 검증

귀로 확인할 수 없는 만큼 잴 수 있는 건 다 잰다.

**소리 (36종)** — `OfflineAudioContext`로 실제 신호 경로 그대로 렌더링해서
- 소리가 나는가, 음량이 균일한가 (전부 피크 0.45 부근, 자동 정규화)
- **밝기가 카테고리에 맞는가** — 킥 189Hz, 하이햇 7168Hz
- **킥·톰의 피치가 실제로 떨어지는가** — 129→52Hz
- 홀드가 유지되고 뗄 때 끊기는가
- 36종이 스펙트럼 지문으로 서로 구별되는가

> 앞선 버전이 "소리가 전혀 다르다"는데도 검사를 통과했던 이유는 **구별도만 보고
> "킥이 킥처럼 생겼나"를 안 봤기** 때문이다. 밝기·피치 검사는 그래서 추가했다.

**앱** — Playwright 98항목. 게이트, 동시 타격, 홀드, 롤, choke, 라이브러리 교체,
조음 슬라이더, 탐색 저장, 녹음→스냅→재생→레이어→언두, 시퀀서, 속도 훈련,
공유 링크 왕복, WAV 렌더, 세로/가로 레이아웃, 콘솔 에러 없음.

## 남은 것

- **소리를 귀로 검수해야 한다.** 36종은 해부학과 고전 타악 합성으로 추정한 값이라
  틀린 게 있을 수 있다. 고치는 건 쉽다 — 「조음」에서 슬라이더 하나다
- 소리 계속 늘리기 (참고: Onyx Beatbox의 «All (Almost) Known Beatbox Sounds», 544종)
- 마이크 인식 — 입력을 포먼트로 분석해 지금 낸 소리의 좌표를 추정하고,
  목표와 비교해 "혀를 더 뒤로" 같은 지시를 주는 것. 증강 루프가 여기서 닫힌다
