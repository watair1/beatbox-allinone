# 비트박스 올인원

비트박스 **사운드보드 → 루프스테이션 → AI 인식** 순서로 쌓아 올리는 웹앱.
음원 파일 없이 Web Audio API로 소리를 직접 합성한다.

`index.html` 하나가 전부다. 빌드 도구도, 의존성도, 서버도 없다.
(`sw.js`는 오프라인 캐시 전용이고, 없어도 앱은 그대로 동작한다.)

## 흐름도

```mermaid
flowchart TD
    A([앱 실행]) --> B[시작 게이트<br/>“시작하기”]
    B -->|첫 사용자 제스처| C[AudioContext 생성 + resume]
    C --> D[패드 8개 화면]

    D --> E{입력}
    E -->|터치 pointerdown| F[play&#40;패드&#41;]
    E -->|키 왼손 ASDF · 오른손 JKL;| F

    F --> G{AudioContext<br/>running?}
    G -->|아니오| H[resume&#40;&#41;] --> I
    G -->|예| I[소리 합성 · 스케줄]
    I --> J[패드 발광 + 리플 + 카운터 &#43;1]
    J --> D

    D -.v0.2.-> K[REC → 타이밍 기록]
    K -.-> L[STOP → 루프 반복 재생]
    L -.-> M[루프 위에 레이어 추가]
    D -.v0.3.-> N[마이크 → AI 분류 → 패드 매핑]
```

글로 쓰면 이렇다.

1. 앱을 켜면 **시작 게이트**가 먼저 뜬다
2. `시작하기`를 누르는 순간 AudioContext가 열린다 — 브라우저 정책상 이 제스처가 반드시 먼저 있어야 한다
3. 패드 4개가 보인다
4. 터치하거나 키를 눌러 소리를 낸다. **두 손가락으로 동시에 칠 수 있다**
   · 왼손 `A` `S` `D` `F` = 왼쪽 열, 오른손 `J` `K` `L` `;` = 오른쪽 열, `SPACE` = 킥
5. **가운데를 치면 세고 가장자리로 갈수록 약하다.** 세기만큼 밝게 빛나고 크게 번진다
6. 두 개 이상이 함께 울리면 한가운데에 `킥 ＋ 하이햇` 배지가 뜬다
7. `REC`를 누르고 비트를 친다 → 타이밍이 기록된다 *(v0.2)*
8. `STOP`을 누르면 루프로 반복 재생된다 *(v0.2)*
9. 루프 위에 레이어를 하나 더 쌓는다 *(v0.2)*
10. 마이크로 비트박스하면 AI가 분류해서 패드에 매핑한다 *(v0.3)*

## 동시 타격 설계

혼자 치는 사운드보드와 악기를 가르는 건 **두 개를 같이 낼 수 있느냐**다.
`킥+하이햇`, `스네어+하이햇`은 비트의 기본 골격이라 이게 안 되면 박자를 칠 수가 없다.

### 배치 — 자주 겹치는 조합을 서로 다른 엄지에

```
세로                        가로
┌────────┬────────┐         ┌──────┬──────┬──────┬──────┐
│  킥 A  │하이햇 J│         │ 킥 A │스네어│하이햇│오픈 K│
├────────┼────────┤         ├──────┼──────┼──────┼──────┤
│스네어 S│오픈햇 K│         │ 톰 D │림샷 F│클랩 L│크래시│
├────────┼────────┤         └──────┴──────┴──────┴──────┘
│  톰 D  │ 클랩 L │            └─ 왼손 ─┘  └─ 오른손 ─┘
├────────┼────────┤
│ 림샷 F │크래시 ;│
└────────┴────────┘
  왼엄지     오른엄지
   왼손       오른손
```

- 왼쪽 열은 드럼 몸통, 오른쪽 열은 심벌·박수
- 그래서 `킥+하이햇`, `스네어+하이햇`이 **항상 좌우 다른 엄지**에 걸린다
- 하이햇과 오픈햇은 서로 choke 관계라 **애초에 같이 울릴 수 없으므로** 같은 엄지에 묶어도 손해가 없다
- 킥+스네어 동시는 실제로 거의 안 쓴다. 그래서 같은 엄지(왼쪽 열)로 몰았다
- 키보드도 같은 원리다. 왼손 `A` `S` `D` `F` = 왼쪽 열, 오른손 `J` `K` `L` `;` = 오른쪽 열.
  화면의 좌우 분할이 손의 좌우 분할과 그대로 맞는다

처음 배치(킥·스네어 / 하이햇·오픈햇 순서)는 정확히 이 반대였다.
제일 많이 쓰는 조합이 한 엄지에 겹쳐 있었고, 절대 같이 못 울리는 둘이 양손에 갈라져 있었다.

### 손가락마다 따로 추적

`pointerId`별로 상태를 들고 있어서 몇 개를 올리든 각자 울리고, 각자 링이 퍼지고,
누르고 있는 동안 해당 패드 테두리가 켜져 있다. 키보드도 마찬가지로 여러 키가 동시에 먹는다.
킥은 다른 손 엄지로 칠 수 있게 `SPACE`도 받는다. `Shift`를 같이 누르면 강타다.

### 쓸어서 굴리기

손가락을 뗀 채로 패드를 가로질러 쓸면 지나가는 패드마다 울린다(드럼 롤).
같은 패드 안에서 꼼지락대는 건 무시하고, **다른 패드로 넘어갈 때만** 발사한다.

### "동시"를 어떻게 판정하나

시간만으로 판정하면 빠른 롤까지 조합으로 오인한다.
진짜 기준은 **손가락이 다른가**다 — 같은 `pointerId`가 쓸고 지나간 소리는 아무리 빨라도 조합이 아니다.
서로 다른 입력원이 60ms 안에 들어온 경우만 조합으로 센다.
덕분에 창을 넉넉히 잡아도 롤이 오인되지 않는다.

### 소리는 맞추지 않는다

두 손가락이 "동시에" 닿아도 이벤트는 보통 5~20ms 어긋나 도착한다.
이걸 한 시각으로 맞추려면 그만큼 **미리보기 지연**을 깔아야 하는데, 드럼 패드에서 지연은 어긋남보다 훨씬 나쁘다.
게다가 음색이 다른 타악기 두 개는 20~30ms 안쪽이면 사람 귀에 한 방으로 붙어 들린다.
그래서 정렬하지 않고 바로 낸다. (같은 JS 태스크에서 처리된 타격끼리는 `currentTime`이 그대로라 자연히 정렬된다.)

## 엣지 케이스 체크리스트

### v0.1에서 처리한 것

- [x] **브라우저가 첫 제스처 전엔 소리를 막음** → `시작하기` 게이트 화면.
      버튼을 누른 그 순간에 `AudioContext`를 만들고 `resume()` 한다.
      `resume()`은 프로미스라 실패할 수 있어서, 실패해도 화면은 열고 상태 배지로 알린다.
- [x] **하이햇 choke** — 닫힌 하이햇이 울리던 오픈 하이햇을 끊는다.
      뚝 자르면 딸깍 소리가 나므로 28ms에 걸쳐 닫는다.
      오픈햇이 울리는 동안은 패드의 점이 깜빡여서 "지금 choke 대상"임이 보인다.
- [x] **키를 꾹 누르고 있을 때 연속 발사 방지** — `e.repeat`과 자체 `held` 집합을 둘 다 본다.
      탭을 벗어나면 `keyup`을 못 받아 키가 눌린 채로 남으므로 `blur`에서 초기화한다.
- [x] **폰에서 화면 껐다 켜면 AudioContext가 멈춤** → 두 겹으로 막았다.
      `visibilitychange`에서 되살리고, 그와 별개로 **재생 직전에 매번** 상태를 확인한다.
      (iOS는 `suspended` 말고 `interrupted` 상태도 쓰기 때문에 `state === 'suspended'`가 아니라
      `state !== 'running'`으로 검사한다.)
- [x] **사용자가 폰이면?** → 터치가 1순위, 키보드는 보너스.
      `click`이 아니라 `pointerdown`이라 300ms 지연이 없고, 멀티터치로 두 패드를 동시에 칠 수 있다.
      패드에 `touch-action:none`을 줘서 연타가 스크롤로 새지 않는다.
- [x] **자주 쓰는 조합이 한 엄지에 겹침** → 배치를 뒤집어 좌우로 갈랐다. 위 「동시 타격 설계」 참조
- [x] **빠른 롤이 동시 타격으로 오인됨** → 시간이 아니라 입력원(`pointerId`)으로 판정
- [x] **패드 밖에서 손을 떼면 눌린 상태로 남음** → `pointerup`/`pointercancel`을 창 전체에서 받는다
- [x] **스페이스로 킥을 치면 페이지가 스크롤됨** → 매핑된 키는 전부 `preventDefault`
- [x] **같은 악기에 키가 둘(`A`/`SPACE`)일 때 표시가 꼬임** → 눌림 상태를 악기가 아니라 **키 단위**로 들고,
      뗄 때 같은 악기를 가리키는 다른 키가 아직 눌려 있는지 확인한다
- [x] **연타하면 소리가 찌그러짐** → 마스터에 리미터(DynamicsCompressor)를 물렸다.
- [x] **연타하면 애니메이션이 안 다시 돔** → `hit` 클래스를 뗀 뒤 리플로우를 강제하고 다시 붙인다.
- [x] **이미 지나간 시각에 노드를 예약하면 클릭 노이즈** → 항상 `currentTime + 1ms`에 스케줄한다.
- [x] **게이트가 사라져도 DOM에 남아 클릭을 먹음** → `#gate[hidden]{display:none}`.
      (`#gate{display:flex}`가 id 선택자라 `[hidden]` 기본 규칙을 이겨버린다. 실제로 밟았던 버그다.)

## v0.2 최대 난제 — 루프 길이는 뭐가 정하나

정답이 없어서 미리 적어둔다. 셋 중 하나를 골라야 한다.

| 방식 | 어떻게 | 좋은 점 | 나쁜 점 |
| --- | --- | --- | --- |
| **첫 녹음 길이** | `STOP` 누른 순간까지가 1루프 | BPM을 안 물어봐도 됨, 자유로움 | 끝을 어설프게 끊으면 루프가 절뚝거림 |
| **고정 마디** | BPM + 4마디를 먼저 정하고 그 안에 녹음 | 레이어가 항상 딱 맞음 | 시작 전에 BPM을 정해야 함 = 진입 장벽 |
| **첫 녹음 + 자동 스냅** | 첫 녹음 길이를 재고 가장 가까운 마디로 반올림 | 자유로우면서 안 절뚝거림 | 구현이 제일 어렵고, 스냅이 틀리면 더 이상함 |

현재 생각: **첫 녹음 길이 + 자동 스냅**으로 간다.
"REC 누르고 그냥 치면 된다"가 이 앱의 핵심이라 BPM을 먼저 묻는 순간 그게 깨진다.

## 소리를 어떻게 만드나

파일 없이 오실레이터와 노이즈 버퍼로 합성한다.

| 패드 | 합성 방식 |
| --- | --- |
| **킥** | 사인파 150Hz → 50Hz 스윕(110ms) + 게인 감쇠(420ms). 어택에 4ms 램프를 줘서 딸깍 소리를 없앰 |
| **스네어** | 7kHz 하이패스 노이즈(190ms) + 180Hz 삼각파(130ms)를 겹침 |
| **하이햇** | 7kHz 하이패스 노이즈, 감쇠 **60ms** |
| **오픈 하이햇** | 같은 노이즈, 감쇠 **450ms**. 닫힌 하이햇이 들어오면 choke |

노이즈 버퍼는 0.5초짜리 하나를 만들어 두고 `loop = true`로 재사용한다
(오픈햇 감쇠가 버퍼보다 길어져도 끊기지 않게).

신호 경로: `소스 → 필터 → 게인 → 마스터 게인 → 리미터 → 스피커`

## 검증

Playwright + Chromium으로 확인했다.

**UI** — 25개 항목을 자동으로 검사한다. 게이트 동작, 패드 4개 발성, 꾹 누르기 1발,
choke, 세로/가로 레이아웃과 스크롤 0px, 터치 타깃 44px 이상, 콘솔 에러 없음. 동시 타격 쪽은 특히:

- 킥↔하이햇, 스네어↔하이햇이 좌우 다른 엄지 영역에 있는지 **좌표로** 확인
- 하이햇↔오픈햇(choke 관계)은 같은 쪽에 있는지 확인
- 손가락 2개 → 2 hits + `킥 ＋ 하이햇` 배지, 3개 → 3화음 배지
- 한 손가락으로 쓸면 2 hits(롤), 같은 패드 안 미세 이동은 1 hit
- 빠른 한 손가락 롤이 조합으로 오인되지 않음
- 키보드 2키 동시, `A` 홀드 중 `SPACE`도 따로 울림

**소리** — 합성 함수를 `OfflineAudioContext`에 실제 신호 경로 그대로 렌더링해서 파형을 쟀다.

```
        peak     100ms 구간별 RMS
kick    0.329    0.179  0.053  0.006  0.001
snare   0.243    0.050  0.002  0
hat     0.080    0.009  0                      ← 짧게 끊김
open    0.244    0.068  0.025  0.004  0.001    ← 길게 남음
choke   0.934    0.186  0.211  0.000           ← 닫힌햇(150ms) 이후 뚝
```

오픈햇 단독일 때 0.2~0.3초 구간 RMS가 `0.0039`, 닫힌햇으로 choke하면 `0.0001`.
choke가 실제로 소리를 끊는다는 뜻이다. 모든 peak가 1.0 아래라 클리핑도 없다.

## 왜 만드나

1. 머릿속 비트를 바로 찍어볼 수 있다 — 지금은 입으로 하고 그냥 사라진다
2. 비트 아이디어가 기록으로 남는다
3. 비트박스 × AI = 내 영토. 둘 다 하는 사람이 거의 없다
